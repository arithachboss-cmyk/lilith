## หน้านี้ชนกับสองหน้า ไม่ใช่หน้าเดียว

ปกติหน้ารองใน cluster ต้องเลี่ยงการทับหน้าหลักของ cluster ตัวเอง
หน้านี้มีเพื่อนบ้านสองฝั่ง เพราะมันอยู่ตรงรอยต่อของ C-3 (RFID) กับ C-5 (คลัง)

| หน้า | cluster | คำถามที่หน้านั้นตอบ |
|---|---|---|
| `/rfid-systems` | C-3 หลัก | ระบบ RFID มีอะไรบ้าง |
| **หน้านี้** | C-3 รอง | **ระบบ RFID ในคลังกินขอบเขตแค่ไหน** |
| `/knowledge/rfid-warehouse-implementation` | C-3 รอง | ติดตั้งตามลำดับอย่างไร |
| `/warehouse-data-capture` | C-5 หลัก | จุดไหนในคลังที่ข้อมูลขาด (ไม่ผูกกับเทคโนโลยีใด) |

เส้นแบ่งที่ใช้: `/warehouse-data-capture` ตั้งโจทย์โดยไม่เลือกเทคโนโลยี
**หน้านี้ตอบโจทย์นั้นด้วย RFID โดยเฉพาะ และจำกัดตัวเองไว้ที่คำถามเรื่องขอบเขต**
บทความจึงลิงก์ข้าม cluster ไปหา `/warehouse-data-capture` อย่างชัดเจน แทนที่จะเขียนเนื้อหาเดียวกันซ้ำ

## Canonical intent

ให้วิธีขีดขอบเขตของระบบ RFID ในคลังด้วยสี่คำตอบ แล้วแยกงานที่การอ่านอัตโนมัติเปลี่ยนจริง
ออกจากงานที่ยังต้องมีคนตัดสิน

**ไม่ครอบคลุม:** ลำดับเวลาของการติดตั้ง · ส่วนประกอบของระบบ · ตัวเลขทุกชนิด

| # | หัวข้อ | เหตุผล |
|---|---|---|

| H2 | ขอบเขตถูกกำหนดด้วยสี่คำตอบ | อะไรติดป้าย · ติดตอนไหน · อ่านที่ไหน · ผลไปไหน |

| H2 | จุดที่ยังต้องมีคนตัดสิน | สี่ข้อ — เป็นส่วนที่กันไม่ให้บทความกลายเป็นคำโฆษณา |
