# AMI — HUMAN + AI COMMAND · หน้าจอส่วนบุคคล 6 ตำแหน่ง

Prototype หน้าจอหลังเข้าสู่ระบบสำหรับ HR + AI / Middle Property
**ข้อมูลทั้งหมดเป็นข้อมูลสังเคราะห์** ไม่มีอีเมลจริง ชื่อบุคลากรจริง ข้อมูลลูกค้าจริง
รหัสผ่าน key หรือ token และไม่มีการเชื่อมต่อบริการภายนอกใด ๆ

## เปิดดู

```bash
node hr-screens/serve.mjs        # เปิดที่ http://127.0.0.1:4300
```

เปิดหน้าจอเฉพาะบทบาทได้ด้วย hash เช่น `#role=HR-05`
และเปิดสำนักงาน 100 เอเจนต์ที่ `http://127.0.0.1:4300/office.html` (ลิงก์ตรงถึงเอเจนต์ เช่น `#agent=AGT-019`)

รวมเป็นไฟล์เดียวสำหรับแชร์หรือฝัง (อ่านจากไฟล์ต้นทางเสมอ ไม่มีสำเนาที่หลุดเวอร์ชัน):

```bash
node hr-screens/build-single.mjs                          # dist/prototype.html + dist/office.html
node hr-screens/build-single.mjs --page=office            # เฉพาะหน้าสำนักงาน
node hr-screens/build-single.mjs --fragment --out=<path>  # ไม่มี doctype/head/body (--page=screens|office)
```

HTML/CSS/JavaScript ล้วน ไม่มี framework ไม่มี dependency ไม่แตะ lockfile
และอยู่นอก glob `apps/*` กับ `packages/*` จึงไม่กระทบ build ของ LILITH

## หมายเหตุเรื่องไฟล์ต้นฉบับ

บรีฟอ้างถึง `hr-gateway.html`, `hr-gateway.css`, `hr-gateway.js`, `assets/hr-orbit.jpg`
และ `docs/hr-ai-role-registry.md` — **ไฟล์เหล่านี้ไม่ได้ถูกแนบมาและไม่มีในรีโปนี้**
งานชิ้นนี้จึงยึดบรีฟเป็นฐานตามที่บรีฟระบุไว้เอง และ **ยังไม่ได้ตรวจไฟล์ต้นฉบับ**
ภาพวงโคจรใช้การไล่แสงด้วย CSS แทนไฟล์ `hr-orbit.jpg` ที่ยังไม่ได้รับ

## Design direction

**กองบัญชาการที่อ่านออกก่อน แล้วจึงสง่า** โทนพื้น deep navy ถึง near-black
ตัวอักษร ivory เส้นและแสง cyan แต้ม champagne gold โลกจากวงโคจรทำเป็นแสงไล่ที่ขอบล่าง
ไม่ใช่ภาพประกอบเต็มจอ เพราะหน้าจอนี้ต้องใช้ทำงานทุกวัน ไม่ใช่ดูครั้งเดียว

**การอวยยศอยู่ที่ภาษาและตรา ไม่ใช่ที่สิทธิ์** แต่ละบทบาทได้ mission passport ของตัวเอง
— ตราภารกิจ ชื่อพื้นที่ call sign และ Grok ประจำตำแหน่ง — และคำต้อนรับที่พูดถึงคุณค่า
ของงานนั้นตรง ๆ ไม่มีการสร้างตำแหน่งใหม่ ไม่มีการอ้างการเลื่อนตำแหน่ง
และไม่มียศตกแต่งใดที่แปลงเป็นสิทธิ์ระบบ

**ทุกบทบาทมีน้ำหนักเท่ากัน แต่บุคลิกไม่เหมือนกัน** โครงหน้าเหมือนกันทั้ง 6 จอ
(passport → ภารกิจวันนี้ → แผงของบทบาท → AI คู่คิด → คำขอผู้เชี่ยวชาญ → ขอบเขตอำนาจ)
สิ่งที่ต่างคือสีเน้น ตราภารกิจ และรูปแบบแผงกลางซึ่งมาจากลักษณะงานจริงของตำแหน่งนั้น

**ขอบเขตอำนาจเป็นส่วนหนึ่งของการออกแบบ ไม่ใช่ disclaimer ท้ายหน้า** ทุกจอมีแผง
“ขอบเขตอำนาจของหน้าจอนี้” ที่บอกว่าตำแหน่งนี้ไม่ได้อะไรบ้าง และหลักสี่ข้อ
Human owns accountability · Grok supplies intelligence · AMI controls authority ·
The Keeper controls disclosure แสดงอยู่ในทุกหน้าจอ

**ที่ไม่ทราบ ต้องเขียนว่าไม่ทราบ** สถานะ “ไม่มีสิทธิ์เข้าถึง” ไม่ได้พูดว่าถูกปฏิเสธ
แต่พูดว่า *ยังไม่ทราบสิทธิ์ของคุณสำหรับข้อมูลชุดนี้* และต้องผ่านทั้ง AMI permission
กับ Keeper disclosure ก่อน ระบบไม่เดาว่าเข้าถึงได้

## สถานะที่ออกแบบไว้

ทุกหน้าจอมีตัวเลือก **“สถานะตัวอย่าง”** บนแผงกลาง เพื่อดูสถานะจริงทั้งห้าแบบ

| สถานะ | ข้อความที่ผู้ใช้เห็น |
|---|---|
| พร้อมใช้งาน | เนื้อหาปกติ |
| กำลังโหลด | “กำลังโหลดข้อมูล — กำลังดึงข้อมูลที่คุณมีสิทธิ์เห็น” + skeleton |
| ยังไม่มีข้อมูล | “ยังไม่มีข้อมูลในช่วงนี้ — เมื่อมีงานเข้ามา รายการจะขึ้นที่นี่ ยังไม่ต้องทำอะไรตอนนี้” |
| เกิดข้อผิดพลาด | “โหลดข้อมูลไม่สำเร็จ — ข้อมูลที่เห็นก่อนหน้านี้อาจไม่ใช่สถานะล่าสุด” + ปุ่มลองอีกครั้ง |
| ไม่มีสิทธิ์เข้าถึง | “ยังไม่ทราบสิทธิ์ของคุณสำหรับข้อมูลชุดนี้ … ระบบจะไม่เดาว่าคุณเข้าถึงได้” |

สถานะ **AI ยังไม่เชื่อมต่อ** แสดงถาวรบนแผง AI คู่คิดทุกหน้าจอว่า
“กำหนดบทบาทแล้ว · รอเชื่อมต่อ” และย้ำว่ายังไม่มีการเชื่อม xAI, AMI Core หรือ THE KEEPER

## การเข้าถึงด้วยคีย์บอร์ดและการอ่าน

- แถบบทบาทเป็น `role="tablist"` เลื่อนด้วยลูกศรซ้าย/ขวา/บน/ลง และ Home/End
- ลิงก์ข้ามไปเนื้อหาหลักเป็นสิ่งแรกที่โฟกัสได้
- โฟกัสเห็นชัดทุกองค์ประกอบ (เส้น cyan หนา 2px มี offset)
- การเปลี่ยนหน้าจอและผลลัพธ์ของปุ่มประกาศผ่าน `aria-live`
- ไม่มีเสียง ไม่มีแอนิเมชันบังคับ และเคารพ `prefers-reduced-motion`
- ตัวอักษรไทยอยู่ที่ 15.5–16px บนมือถือ ใช้ฟอนต์ระบบที่รองรับไทย ไม่โหลดฟอนต์ภายนอก

## ตรวจแล้วด้วยการเรนเดอร์จริง

เรนเดอร์ด้วย headless Chromium ที่ความกว้าง 485 / 585 / 753 / 1009 / 1400 px
ทุกความกว้าง `scrollWidth == clientWidth` คือไม่มีการล้นแนวนอน
ยกเว้นแถบบทบาทกับ lane board ซึ่งตั้งใจให้เลื่อนแนวนอนได้เอง

**ข้อจำกัดของการตรวจ:** headless Chromium ในเครื่องนี้บังคับ viewport ต่ำสุดที่ 485px
จึงยังไม่ได้ตรวจที่ความกว้างต่ำกว่านั้นด้วยการเรนเดอร์จริง
(breakpoint ที่ ≤560px ถูกใช้งานแล้วที่ 485px)
