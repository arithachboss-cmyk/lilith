4c. PNG upload validation — Genuinely rigorous, not a formality

Evidence: src/services/pilot-image.ts::validImage.

Real per-chunk CRC-32 verification (manual IEEE 802.3 polynomial implementation), rejects a duplicate IHDR chunk, restricts to bit-depth 8 / non-interlaced / color types 0,2,4,6 (correctly rejects palette-indexed PNGs, matching the documented scope).
Decompression-bomb defense, confirmed correct: caps decompressed size at 8 * 1024 * 1024 bytes before decompressing, and aborts mid-stream the instant the running total exceeds the IHDR-declared stride * height. Combined with the 128 KB compressed-input cap enforced earlier in putImage, this closes the classic "tiny file claims huge dimensions" zlib-bomb vector — a control many naive image validators skip.
Correctly uses DecompressionStream("deflate") (zlib/RFC1950-wrapped), which matches PNG's actual IDAT container format (not "deflate-raw", which would be wrong here) — I verified this is the technically correct choice.
Scanline filter-byte range (0–4) is validated per PNG spec.

Verdict: No defect. This is above-baseline security engineering for an image upload path.
